Build Hierarchy Overview

The Build Hierarchy and Position Rules tab is used to define the physical structure of the Model and the configuration rules which form part of the allowed configuration.

Overview​

The "Build Hierarchy and Position Rules" tab provides the user with the means to define the structure of a complex asset type.
It allows the definition and visualisation of the parent/child relationship between the Build Positions.

The image below shows an example Build Hierarchy, formed from the Models Build Items, for a Rapid Transit Metro Train:

New positions can be added to the Model by right clicking a node and selecting the option "New Child" or "New Sibling". The dialog which is opened allows the user to specify the attributes for the new position:

Altering the Build Hierarchy​

Positions can be freely added, moved (using the Move Up/Down and Push/Up down) or deleted from the Build Hierarchy in the situation where NO Assets have been created from the Model.

Once Assets are created from the Model then restrictions are imposed in terms of the movement of Build Positions.
This is enforced as the LCN value of a position is used, as part of the Assets as maintained configuration history, to record which assets have been installed into a position over the assets lifecycle.

If assets have been created then it is possible to add new positions (with new, unique, unused LCN values) and also delete build positions.

New in Maximo ACM 9.1.x

In the situation where a build position is deleted a record is created to record that the associated LCN value has been previously used for this Model.
When new Build Positions are added these previously used LCN values are by default "skipped" when generating the LCN value for the new position.

Previously used LCN values can be viewed and managed using the action "View Used Build Position LCNs".
